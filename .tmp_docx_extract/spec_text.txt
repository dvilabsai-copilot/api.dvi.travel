📘 Smart Itinerary Optimization Engine – Functional & Business Specification
🧭 1. Overview
The system aims to build a dynamic, intelligent travel itinerary engine that:
Automatically selects and orders hotspots (places to visit)
Optimizes routes based on priority, time, distance, and constraints
Supports real-time user customization
Handles activities (fixed-time events)
Adapts to multi-day and multi-city travel
Recalculates instantly on any change
🎯 2. Core Objectives
Maximize coverage of high-priority hotspots
Minimize travel time and route inefficiencies
Respect real-world constraints:
opening/closing timings
travel time
user availability
Provide flexibility with control (user edits with system validation)
Deliver agent-grade itinerary automation
🧩 3. Key Concepts
3.1 Hotspots
Tourist places with:
priority (1–N)
location
opening hours
visit duration
day availability
3.2 Activities
Special time-bound experiences:
paragliding, laser show, safari, etc.
fixed or semi-fixed time slots
consume large time blocks
act as hard constraints
3.3 Day Slots
Each day is divided into:
Morning Slot → (e.g., 08:00–14:00)
Evening Slot → (e.g., 16:00–20:00)
👉 Gap accounts for:
lunch
travel buffer
closed timings (temples etc.)
3.4 Priority Model
Priority
Meaning
1
Must visit
2
High importance
3
Important
4+
Optional / fillers
👉 Only 1, 2, 3 are strict priorities👉 4+ are used for gap filling (distance-based)
⚙️ 4. Core Planning Logic
🔹 Step 1: Initialize Constraints
System locks:
day start & end time
city / route (Madurai → Trivandrum)
travel durations
hotspot availability
user-selected activities
🔹 Step 2: Place Activities First
Activities are treated as:
👉fixed time blocks (appointments)
System:
reserves activity slots
blocks those time ranges
builds itinerary around them
🔹 Step 3: Place Top Priorities (1, 2, 3)**
For each priority:
Check:
is it open?
does it fit in current slot?
is travel time feasible?
If YES → place it
If NO → defer to next slot (morning → evening)
🔹 Step 4: Fill Remaining Time
Remaining slots are filled using:
👉Nearest Distance Logic
Next hotspot = closest to last visited location
Applies only for:
priority 4+
leftover lower priorities
🔁 Step 5: Re-routing After Deferred Items
If a priority hotspot is deferred:
system rearranges route
fills earlier slots with alternatives
re-inserts deferred hotspot later
again continues nearest-distance logic
⏱️ 5. Time Constraint Engine
Each hotspot is validated against:
opening time
closing time
visit duration
travel buffer
day availability
Rule:
IF hotspot cannot fully fit in time slot
→ DO NOT place
→ defer or skip
📆 6. Multi-Day Logic
Day 1:
priority 1,2,3 first
fill with nearby 4+
Day 2+:
include leftover hotspots
still prioritize missed top priorities
rest → distance-based selection
Carry Forward Rule:
Missed hotspots from Day 1
→ moved to Day 2
→ reprocessed with same logic
🚗 7. Intercity Travel Logic
Example:Madurai → Kanyakumari
Default Flow:
Morning:
complete remaining source city hotspots
Travel:
move to next city
If time permits:
visit destination hotspots
End:
hotel check-in
Direct Destination Option
If enabled:
skip source city sightseeing
travel directly to destination
Via Route Logic
Example:Chennai → Pondicherry (via Mahabalipuram)
Flow:
start → Chennai
visit → Mahabalipuram
end → Pondicherry
👤 8. User Customization Engine
Case 1: Add Hotspot
System checks:
time fit
travel feasibility
Outcomes:
Result
Action
Fits
Add + reroute
Doesn’t fit
Show warning
Case 2: Remove Hotspot
remove from itinerary
fill gap using nearest available hotspot
Case 3: Modify Day Timing
User changes:
start time
end time
If time decreases:
remove lower-priority hotspots
preserve 1,2,3
reroute
If time increases:
add more hotspots
include missed priorities
fill with nearest options
Rule:
👉Any change triggers full re-optimization
🎢 9. Activity Handling Logic
Activities = High-impact constraints
Case 1: Activity fits
reserve slot
reroute around it
adjust nearby hotspots
Case 2: Activity conflicts with top priorities
System must:
try rerouting
defer top priorities if possible
if still conflict → warn user
Warning Levels:
✅ Green: no impact
🟡 Yellow: optional hotspots moved
🟠 Orange: priority shifted
🔴 Red: priority lost → block or warn
🧠 10. Optimization Strategy
Combined Approach:
1. Priority-first selection
2. Time-window validation
3. Greedy nearest-neighbour routing
4. Constraint-based scheduling
Problem Type:
👉 Variant of Travelling Salesman Problem (TSP)with real-world constraints
