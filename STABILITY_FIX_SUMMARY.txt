TIMELINE CORRUPTION FIX SUMMARY
=============================

ISSUE: Day 3 (Route 4648: Munnar → Alleppey) has corrupted timeline with:
- Self-travel rows (e.g., INTERNATIONAL COIR MUSEUM → INTERNATIONAL COIR MUSEUM)
- Overlapping attractions (Coir Museum 11:28 AM-12:58 PM overlaps Backwater 12:00 PM-3:00 PM)
- Impossible Revi timing (displayed after travel but starts before arrival)
- Wrong break duration calculation (4h 9m displayed instead of 2h 47m)
- Inflated route distance (321.43 KM with duplicates)

ROOT CAUSE: Previous waiting-gap filler updates introduced unsafe mutations:
1. hotspotMap only stored 4 fields (location, lat, lon, duration)
   → Missing hotspot_name, hotspot_type, hotspot_priority, hotspot_to_location
   
2. candidateLocationName used hotspot_location (city name) instead of hotspot_name
   → City name "Alleppey" treated as attraction name in travel labels
   → Led to wrong same-city matching and self-travel insertion
   
3. buildFreeTimeBreakRow used simple time subtraction for duration
   → Wrapped times (e.g., 02:13 PM after 14:00 wrapping) caused negative duration
   → Wrong break hours displayed (4h 9m instead of 2h 47m)
   
4. No timeline validation before returning rows
   → Corrupted rows silently stored in database
